## Gợi ý thứ tự đọc

1. **Bảng config (1 → 7):** đọc #1 trước để thuộc **bộ số Kafka 4.3** (120000 / 30000 / 5 / 16384 / 32 MB / 60000 / 1 MB / 5 in-flight / 60000 txn); #7 chỉ để đối chiếu — đừng đọc lại toàn bộ.
2. **API & hành vi (2 → 8):** #2 cho thread-safety, `send()` async, mẫu code transaction và quy tắc xử lý exception (fatal → `close()`); #8 cho đường đi record (serializer → partitioner → accumulator → sender) và bảng perf-test để hiểu **vì sao tăng `linger.ms` không phải lúc nào cũng lợi**.
3. **Semantics (3):** đọc trước khi vào transactions — nắm chắc at-most/at-least/exactly-once + 2 cách commit offset của consumer + `read_committed`.
4. **Transactions (4):** đọc sau #3 và trước Lab 3.5 — luồng coordinator/marker/LSO, `transaction.timeout.ms` ≤ `transaction.max.timeout.ms`, chọn `transactional.id` ổn định; phần KIP-890 chỉ cần nhận diện "epoch bump mỗi transaction từ 4.0".
5. **Partitioner (5):** đọc trước Lab 3.3 — hiểu sticky ≠ bug, `partitioner.ignore.keys`, và bẫy "thêm partition đổi mapping key" (bẫy này nằm ở README Buổi A §7).
6. **KIP-1030 (6):** đọc cuối, 5 phút — mục đích duy nhất là **không bị lừa bởi đề cũ ghi `linger.ms=0`**.
